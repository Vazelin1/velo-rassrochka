# Установка (Selectel + Telegram)
1. Telegram: в @BotFather команда /newbot, сохраните токен. Ваш числовой ID узнайте у @userinfobot.
2. Selectel: создайте облачный сервер Ubuntu 24.04 (1 vCPU, 1-2 ГБ), запишите его IP. У регистратора домена создайте запись A: ваш (под)домен -> IP сервера.
3. Подключитесь: `ssh root@IP`. Установите Docker: `curl -fsSL https://get.docker.com | sh`
4. Загрузите папку проекта на сервер (с вашего компьютера: `scp -r velo root@IP:/root/`), затем `cd /root/velo`.
5. `cp .env.example .env`, откройте `nano .env` и впишите токен, ID и домен (без https://).
6. `docker compose up -d --build`. Через минуту адрес https://ВАШ_ДОМЕН должен отвечать.
7. @BotFather: /mybots, ваш бот, Bot Settings, Menu Button, Configure menu button, укажите https://ВАШ_ДОМЕН. Откройте бота в Telegram и нажмите кнопку меню.

# Обновление
Если проект лежит в GitHub: загрузите изменённые файлы в репозиторий (`server.py` в корень, `static/index.html` в папку `static`), затем в консоли сервера:
`cd ~/velo`, `git pull`, `docker compose up -d --build`.
Данные (папка `data`) при обновлении не меняются.

# Администраторы
Владелец: «Настройки», «Администраторы», «Добавить». Нужны имя, телефон и галочки прав (принимать оплаты, досрочные платежи и отсрочки, клиенты, выкупы, велосипеды, отчёты). После сохранения приложение предлагает ссылку для входа: отправьте её администратору. Он открывает ссылку в Telegram и вводит свой номер телефона (должен совпасть с тем, что вы указали, сравниваются последние 10 цифр; 5 попыток в час). Telegram ID привязывается при первом входе.
Права «Выкупы», «Велосипеды» и «Отчёты» открывают закупочные цены, налог и прибыль; без них эти поля скрыты и не меняются. Права проверяет сервер, а не только приложение. Настройки, резервные копии, журнал и список администраторов видит только владелец.
В карточке администратора: «Ссылка для входа» (новая ссылка), «Сбросить доступ» (привязка к Telegram снимается), «Отключить доступ» / «Включить доступ», «Удалить».
Журнал: «Настройки», «Журнал действий»: последние 250 записей, кто что сделал и когда. Если двое правят одну запись одновременно, второй видит «Эти данные только что изменились», экран обновляется, а чужие правки не затираются.

# Уведомления в Telegram
Все сообщения бота по умолчанию выключены. Включаются в «Настройках», блок «Уведомления в Telegram»:
- «Сообщения вам»: сводка в 10:00 («Сегодня платят клиентов: N»), оплата или досрочный платёж, принятые администратором (сумма, период, остаток по графику), входы клиентов и администраторов, неудачные попытки входа, отсрочка клиента. Оплаты, которые вы вносите сами, сообщением не дублируются.
- «Напоминания клиентам»: в 10:00 по Москве за день до платежа и в день платежа, один раз на каждый платёж (просроченным не отправляются), и подтверждение отсрочки. Клиент получает их, если открыл приложение по вашей ссылке.
Сообщения отправляет сервер. Если с сервера недоступен api.telegram.org, они не доходят (ошибка пишется в `docker compose logs app`), приложение при этом работает как обычно. Когда связь появится, достаточно включить выключатели. Если включить выключатель днём, напоминания начнутся со следующего дня в 10:00.

# Главная и «База»
Календарь платежей на неделю на главной свёрнут: нажмите на строку «Сегодня платят …», он раскроется. Число просроченных стоит слева от заголовка «Просрочены, идёт неустойка». Счётчики «Под выкупом» и «Свободно» находятся вверху экрана «База».

# Неустойка в сумме к оплате
При просрочке клиент на главном экране видит «К оплате сейчас»: просроченные платежи плюс неустойка на сегодня. Нажатие на сумму открывает детализацию («Платёж, период 5: 5 900 ₽», «Неустойка за 3 дня просрочки: 159 ₽», «Итого»). В графике у просроченных периодов сумма тоже с неустойкой. У вас та же сумма в списке «Просрочены» и в карточке выкупа, а на экране «Принять оплату» платёж и неустойка показаны отдельно и неустойка пересчитывается при смене даты получения денег.

# Эквайринг, отчёты и чистая прибыль
Эквайринг (комиссия банка с платежей по СБП) задаётся в «Настройках», блок «Налог, эквайринг и неустойка», в процентах. По умолчанию 0: впишите ставку из договора с банком. Он учитывается как налог:
- в калькуляторе и при оформлении выкупа: ставка × вся цена выкупа (с запасом, потому что наличные комиссии не несут); сумма запоминается в выкупе и вычитается из плановой прибыли;
- в «Отчётах»: ставка × деньги, фактически полученные по СБП за выбранный период (наличные и переводы не облагаются).
Период отчёта выбирается раскрывающимся списком вверху «Отчётов»: любой месяц (строго с 1 по последнее число), целый год или всё время. Рядом с каждым пунктом списка видна чистая прибыль. «Квартал» убран, блок «Налог по периодам» из «Аналитики» тоже: налог и эквайринг за выбранный период показаны в «Отчётах».
Чистая прибыль считается по каждому велосипеду отдельно: полученные деньги (после налога и эквайринга) сначала возвращают вложения (закупка, допы, обслуживание), и только то, что получено сверх этого, является прибылью. Пока велосипед не окупился, его прибыль 0; расходы на обслуживание уже окупившегося велосипеда уменьшают прибыль месяца, когда они были. Для выбранного месяца прибыль показана по неделям (с понедельника по воскресенье, крайние недели обрезаны по границам месяца, их сумма равна итогу месяца), для года и всего времени по месяцам. Убытки от списанных велосипедов в чистую прибыль не входят, они показаны отдельной строкой. Ставки налога и эквайринга берутся из текущих настроек и для прошлых месяцев.

# Списание и замена велосипеда
Списание: карточка велосипеда, «Списать» (причина, дата, сумма убытка; по умолчанию «вложено минус получено»). Велосипед уходит в архив, выкуп (если был) закрывается со статусом «списан», убыток попадает в «Отчёты». «Вернуть в парк» отменяет списание.
Замена: карточка выкупа, «Заменить велосипед». График и платежи не меняются, платежи до даты замены относятся к прежнему велосипеду, после неё к новому. Прежний велосипед возвращается в парк или сразу идёт на списание.

# Копии, владелец, логи
Копии базы: сервер каждую ночь в 03:00 (МСК) сохраняет копию в `data/backups` (хранится 30). Кроме того, в приложении (Настройки, «Резервная копия») есть кнопка «Скачать резервную копию»: файл сохраняется на телефон, а на главном экране каждые 3 дня появляется напоминание. Из такого файла базу можно восстановить там же (администраторы и их привязки возвращаются вместе с данными); перед восстановлением сервер сохраняет текущую базу в `data/backups/pre-restore-….db`. Если сервер в России не достаёт до api.telegram.org, сообщения бота (уведомление в 10:00 и т. п.) не приходят, приложение работает без них.
Сменить владельца: `nano .env`, поменять OWNER_ID, `docker compose up -d`.
Логи: `docker compose logs app`.
Необязательные переменные `.env`: `PORT` (по умолчанию 8080), `DATA_DIR` (по умолчанию /data).
